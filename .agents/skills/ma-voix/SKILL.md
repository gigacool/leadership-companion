# Ma voix

Un brouillon réussi est un brouillon que l'utilisateur envoie avec peu de retouches. Il doit sonner comme lui, pas comme un assistant.

## Avant de commencer

1. Dossier du companion : `COMPANION_HOME` si la variable existe, sinon `~/Companion` (`%USERPROFILE%\Companion` sous Windows).
2. Lis `<dossier>/profil/voix.md` et `<dossier>/profil/config.md`. Ce qu'ils disent l'emporte sur les règles ci-dessous.
3. Lis jusqu'à trois fichiers de `<dossier>/profil/exemples/` du même type que le texte à écrire (refus, relance, rapport…), sinon les plus proches. Imite leur longueur, leur ouverture, leur signature et leur niveau de langue. N'en reprends jamais le contenu.
4. Si le profil manque, applique les règles par défaut et dis-le en une ligne après le brouillon.

## Règles par défaut

- Langue de `config.md`, français sinon.
- Le message principal dans la première phrase. Le contexte ensuite, s'il est utile.
- Phrases courtes, voix active, un sujet par phrase.
- Les termes de métier de l'utilisateur tels qu'il les emploie, sans les traduire ni les expliquer.
- Tutoiement ou vouvoiement : ce que dit `voix.md` pour ce destinataire, sinon `tutoiement par défaut`, sinon ce que l'utilisateur emploie dans sa demande.
- Aussi court que le message le permet. Un email de refus tient en quatre phrases ; une relance en deux.

## Interdits

Ces formules signent un texte écrit par une machine. Ne les emploie jamais, même reformulées :

- les ouvertures et fermetures vides : « J'espère que vous allez bien », « n'hésitez pas à revenir vers moi », « je reste à votre disposition », « belle journée » (sauf si les exemples de l'utilisateur les emploient) ;
- les formules d'emphase : « il est important de noter », « force est de constater », « il convient de souligner » ;
- le vocabulaire de présentation : « plonger dans », « dans un monde en constante évolution », « levier », « synergie », « au cœur de », « véritable » ;
- les tournures : « ce n'est pas X, c'est Y », la phrase en deux temps avec deux-points qui annonce une révélation, les apartés entre tirets, les listes de trois adjectifs ;
- les guillemets autour d'un mot inventé, les métaphores, les émojis (sauf si les exemples en contiennent).

## Selon le type de texte

- **Refus** : le non dans la première phrase, une raison en une phrase, une alternative concrète (une date, une personne, un périmètre réduit). Pas d'excuse répétée.
- **Délégation** : ce qui est demandé, pour quand, pourquoi cette personne, ce qu'elle peut décider seule. Une question ouverte pour vérifier que c'est faisable.
- **Relance** : ce qui était attendu et depuis quand, ce dont l'utilisateur a besoin maintenant, une échéance.
- **Rapport** : les faits d'abord, ce qui a avancé, ce qui bloque et ce qui est attendu de qui. Pas de bilan moral.
- **Réponse à un candidat** : vouvoiement sauf indication contraire, la décision ou l'étape suivante dès la première phrase, une date.

## Avant de rendre le brouillon

Relis-le une fois et supprime chaque phrase qui n'apporte rien au destinataire. Vérifie qu'aucun interdit n'a survécu.

## Ce que tu rends

Le brouillon seul, prêt à copier, avec un objet si c'est un email. En dessous, au plus une ligne sur un choix que l'utilisateur voudra peut-être changer (« Je t'ai fait vouvoyer ce destinataire. »). L'utilisateur relit toujours avant d'envoyer.
